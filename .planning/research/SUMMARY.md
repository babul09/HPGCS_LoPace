# Research Summary — Benchmark Scaling and Reliability Fixes

## 1. Stack Recommendations
- **Pytest**: Required for deterministic mathematical modeling tests (Zstandard operations, Centroid hashes).
- **Zstandard Dicts**: `zstd` dictionaries require careful byte-overhead accounting. Research indicates that evaluating zero-reuse bounds with the full dictionary byte size injected per node drastically misrepresents typical LLM operational realities (the dictionary is broadcast once per session, not transmitted recursively).

## 2. Table Stakes vs Differentiators
**Table Stakes:**
- O(1) or fast O(N) adaptive compression selection criteria.
- Deterministic behavior in dictionaries, ensuring `compress(dict(C), input) -> expand(dict(C), payload) == input`.

**Differentiators:**
- Utilizing mathematical heuristics (like data entropy gradients) to decide *before* running compression whether Zstd, Brotli, or Delta patches will win, rather than naive exhaustive trials (`O(k) -> O(1)` selector scaling).

## 3. Architecture Context
- The `evaluation/baselines.py` needs to decouple "theoretical compression dictionary overhead" from "empirical payload compression" inside Zstd runs. 
- The naive `AdaptiveStore` loop currently cascades testing all available compressors. This must be refactored into a predictive algorithm using pre-calculated heuristic triggers mapping to node size, removing geometric `O(N * Compressors)` penalty.

## 4. Warnings and Pitfalls
- **Memory Scaling**: Loading 10k JSON files in-memory before evaluation will crash Linux setups lacking immense swap. Stream nodes using a buffered parser (e.g., `ijson` or chunked line yield) rather than naive `json.load`.
